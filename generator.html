globals.yml generator for Kolla-Ansible

Fill in the deployment parameters — the file assembles live on the right. Settings are saved locally in the browser; nothing leaves this machine.

Deployment parameters

Import an existing file

Paste or drop a globals.yml. The form fills with the values from the file, and from then on the export edits the original instead of rewriting it — comments, key order and entries the generator does not know stay untouched.

Base image

Base distribution of the container images. Must match the images in the registry.

Image tag, for example 2025.1. Should match the kolla-ansible version.

Networking

A free IPv4 address on the management network — not held by any host.

Management/API network interface. Needs an IP address on every node.

External traffic interface. No IP address, no configuration — Neutron takes it over entirely. Several comma-separated interfaces mean several physical networks.

OVS bridges, one per external interface. The counts must match.

API traffic and the Corosync ring. Empty inherits network_interface.

Storage traffic (Ceph). Empty inherits network_interface.

Live migration. Empty inherits api_interface.

Address of the public endpoints. Empty means the same as internal.

Interface that carries the external VIP.

Names and TLS

Name of the internal endpoints in the service catalogue.

Name of the public endpoints. Must differ from the internal one.

Services

ML2 backend. OVN and openvswitch are mutually exclusive.

Source of volumes and images. Kolla does not deploy Ceph — the cluster must already exist.

Octavia

Amphora management network. vlan and flat need a provider network.

Physical network name. Must follow from the external interface list.

Deliberate decisions

Some rules describe a risk the file alone cannot settle. An acknowledgment does not silence the finding — it lowers it to information and records the decision as a comment in the generated file.
